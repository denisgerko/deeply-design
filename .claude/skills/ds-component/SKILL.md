# Компонент

## 1. Сначала поискать готовое

1. **ДС продукта:** `figma.config.json` → `components` и «задача → компонент» в `RECIPES.md`. Часто нужен новый
   **вариант** существующего компонента (`State`, `Size`, `Mode`), а не новый компонент.
2. **Системный кит платформы** (`kit/platforms/<platform>.md`, `nativeKit`, `search_design_system`) — если продукт
   так делает. Kit красится своими цветами → обёртка-компонент, перекрашенная на токены продукта.
3. **Продукт:** как элемент устроен там (`ds-reference-screen/product-dump`). Числа берём оттуда.

Свой компонент — только если готового нет или он объективно не подходит. Причину записать в `decisions`.
В режиме B (ДС продукта подключена библиотекой) компоненты продукта не редактируем — новый компонент делаем
в рабочем файле и пишем в `STATUS.md` → «Предложения в ДС продукта».

## 2. Сборка

- **Auto-layout** везде, где есть поток. HUG — `primaryAxisSizingMode = 'AUTO'` после `resize`, никогда `resize(W, 0)`.
  Абсолютные слои (стекло, выделение, свечение) — `layoutPositioning = 'ABSOLUTE'` с осмысленными constraints.
- **Токены — через `T`** (скрипт собрать `kit/run.py` из файла в scratchpad, см. `CLAUDE.md`). `T` сам знает,
  как в этом продукте заданы токены (переменные, стили, библиотека — `profile`):
  - цвет: `await T.fill(node, 'имя токена')`, `T.stroke(…)`; по роли — `T.fill(node, T.C('accent'))`;
  - текст: `await T.mkText('Текст', T.T('body'), T.C('textPrimary'))` или `T.text(node, 'Имя стиля')`;
  - отступы и радиусы по значению: `T.pad(n, 16, 12)`, `T.gap(n, 8)`, `T.radius(n, 12)` / `'full'` — найдут токен
    в шкале продукта; значения без токена попадут в `T.report().raw` → записать в `decisions.rawValues`;
  - эффект: `T.effect(node, 'имя effect style')`; служебный фрейм без белой заливки: `T.frame('Name', 'VERTICAL')`.
  Нужного токена нет в продукте — не заводить молча, спросить (правило 4).
- **Материалы** (стекло/блюр), если они есть в ДС: инстанс материала продукта абсолютным слоем на всю площадь
  (STRETCH/STRETCH). Нужного варианта нет → новый вариант в набор материала (клон ближайшего).
- **Иконки:** вложенный инстанс называть `Icon`, цвет — через fill внутреннего векторного слоя.
- **Свойства:**
  - варианты — смысловые (`Size`, `State`, `Style`, `Mode`);
  - видимость — BOOLEAN `Show …`; тексты — TEXT; иконки и картинки — INSTANCE_SWAP с `preferredValues`;
  - TEXT/INSTANCE_SWAP-свойство набора — одно значение по умолчанию на все варианты: если текст задаётся вариантом,
    его не делать свойством;
  - после `combineAsVariants` держать ссылки на узлы в массивах и проставлять `componentPropertyReferences` по ним;
  - новый вариант в существующий набор: сначала `set.appendChild(comp)`, потом ссылки на свойства.
- **Картинки разной высоты** в одном месте — SLOT (`component.createSlot()`), а не INSTANCE_SWAP.
- **Description** компонента: источник в продукте, ключевые размеры и токены, правила использования.

## 3. Место на странице

- Страница компонентов по типу (список — `CLAUDE.md` → страницы). Секция-категория, подпись над компонентом
  (клон соседней подписи). Нет секции — создать; затем `ds-pages-tidy/refit-sections`.
- Варианты внутри набора не пересекаются и не выходят за рамку.

## 4. Проверка

`ds-verify`: превью light + dark (`ds-verify/preview`, потом удалить), сравнение с продуктом числами
и скриншотом, token-audit по компоненту; для изменённого — скриншоты экранов, где он уже стоит (`getInstancesAsync`),
и `glass-check.js`, если менялись размеры компонента с материалом.

## 5. Регистрация

`figma.config.json` → `components["Имя"] = { id, key, page, props, source }`. Изменения существующего — дописать
в `props` с датой. Решения пользователя — в `decisions`. Новая задача → компонент — строка в `RECIPES.md`.
