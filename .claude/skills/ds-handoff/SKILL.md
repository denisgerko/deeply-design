# Пакет на аппрув

Источники: `figma.config.json` → `screens`, `flows.<Фича>`, `decisions.<фича>`, `components`; `STATUS.md`
(вопросы, отклонения). В Figma ничего не меняем. Сообщения от имени пользователя не отправляем — только текст.

## 1. Собрать данные

- Ссылки: `https://www.figma.com/design/<WORK_FILE_KEY>/?node-id=<id через дефис>` — секция Light, секция Dark,
  2–3 ключевых экрана.
- Состояния — по экранам секции (имена фреймов), сгруппировать по экрану ТЗ.
- Флоу: вход → переходы → выход (из `flows`).
- Сделано сверх ТЗ и отличия от референса — из `decisions`.
- Открытые вопросы — из `STATUS.md`; разделить: продукту / дизайну / разработке.
- Новые и изменённые компоненты ДС (дата в `props`) — отдельной строкой: их должен увидеть владелец ДС.

## 2. Текст

Язык пользователя, коротко, без жаргона Figma API:

```
<Фича> — макеты на аппрув
Light: <ссылка> · Dark: <ссылка>

Экраны и состояния:
• <Экран> — <состояния через запятую>

Флоу: <вход> → … → <выход>

Сверх ТЗ / отличия от референса:
• …

Новое в ДС: <компоненты> (нужно добавить в библиотеку продукта)

Вопросы:
• Продукту: …
• Разработке: …

Тексты черновые.
```

Для Slack — без markdown-таблиц, списки «•», до ~15 строк. Длинный пакет или его будут пересылать — предложить
страницу-артефакт.

## 3. Версия файла

Предложить пользователю сохранить именованную версию (File → Save to version history, ⌥⌘S) — через MCP это
недоступно. Подготовить название `<Фича> — на аппрув <дата>` и 2–3 строки описания.

## 4. После отправки

- `STATUS.md`, строка фичи: «На аппруве (дата)».
- Пришёл фидбек — правки по нему (`ds-new-feature` → `ds-verify`), затем статус «Аппрув получен (дата)» или список правок.
