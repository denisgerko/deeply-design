# Порядок на страницах компонентов

Страницы компонентов — `profile.pages.components` (всё до разделителя `profile.pages.divider`).
Скрипты берут их оттуда; другой набор — параметр `PAGES='["Имя"]'`.

## 1. Аудит «лишних» (read-only)

1. `ds-pages-tidy/usage-audit` — для каждого компонента/набора: варианты, где стоят инстансы (по страницам),
   внутри каких компонентов, неиспользуемые варианты.
2. **0 инстансов в файле ≠ лишний.** Компонент может стоять в продукте или в другой фиче. Сверить с продуктом и полями
   `source` в реестре.
3. **Дубли по смыслу:** временная доска с инстансами подозрительных пар → скриншот → сравнить → удалить доску.
4. **Мусор внутри компонентов:** скрытые слои без привязки к свойству, свойства без слоёв, пустые фреймы (кроме распорок).
5. **Удаление компонентов — только после явного «да».** Показать список с причинами.

## 2. Раскладка

- Каждый компонент — в SECTION-категории, подпись с названием над ним; внутренние — `… (internal)`.
- `ds-pages-tidy/layout-sections`: группы `{ name, ids }` и шаблон подписи. Существующие подписи переносятся
  (по совпадению текста), недостающие создаются клоном шаблона; компоненты — рядами (шаг 80, ряд до 2600).
- После любых изменений размеров — `ds-pages-tidy/refit-sections` (подгоняет секции и складывает их вертикально).

## 3. Проверка

- `ds-pages-tidy/overlap-check`: нет наложений внутри секций и между вариантами в наборах, варианты не за рамкой набора.
- Скриншоты 1–2 секций. Превью набора сломано, а данные верные — устаревшая отрисовка (`ds-verify/touch-render`).

## 4. Регистрация

`figma.config.json` → `decisions.componentPagesLayout` и `STATUS.md`.
