# Экран продукта как эталон / фон

В варианте A (дубликат продукта) экран обычно уже есть — его достаточно **клонировать** на страницу фичи.
Этот скил — когда экрана нет или он собран не из компонентов (тогда собрать заново, чтобы клонировать дальше).

## 1. Анализ (read-only)

1. `get_screenshot` узла продукта (light, и dark — если есть).
2. `ds-reference-screen/product-dump ROOT_IDS='["…"]'` (с `fileKey` продукта): дерево с размерами, заливками
   (переменная `{имя}` / стиль `«имя»` / сырой hex), радиусами, паддингами и их токенами, text styles, эффектами
   и главными компонентами инстансов. Это же — лучший способ узнать **роли цветов** для `profile.colors`.
3. Пройти сценарий как пользователь: фокус в поле → клавиатура; активность кнопок; пустые и заполненные состояния.

## 2. Соответствие

Каждый элемент → готовый компонент ДС / нативный кит / новый компонент (`ds-component`). Расхождение компонента
с продуктом (паддинг, цвет, радиус) — чинить в компоненте, а не оверрайдом на экране.
Картинки и иконки, которых нет, — `ds-assets`.

## 3. Сборка

- Фрейм экрана: размер — `profile.screen`, фон как на эталоне (`T.fill`), без auto-layout, clip.
- Бары — клон из уже собранного экрана (оверрайды слотов сохраняются).
- Порядок слоёв: контент → нижние элементы → навбар сверху.
- Позиции — до пикселя против дампа (числами, не на глаз).

## 4. Dark, констрейнты, проверка, регистрация

- `ds-reference-screen/dark-clone` (если dark есть в продукте); `ds-constraints`; `ds-verify`.
- `figma.config.json` → `screens` (id, source); `RECIPES.md` — если это новый эталон типа экрана.
