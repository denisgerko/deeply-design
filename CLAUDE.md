# Deeply — новые фичи в Figma

> **Сначала прочитай `WORKING_RULES.md`** — мои правила работы (роль, проверки, раскладка, варианты, хранение). Они действуют для любого продукта.

## Цель

Claude собирает в Figma макеты **новых фич** Deeply из компонентов и токенов **дизайн-системы этого продукта**:
все состояния, light + dark (если они есть в продукте), стрелки флоу, пакет на аппрув. Экраны продукта заново
не пересобираем — только то, что нужно фиче как фон или каркас (`ds-reference-screen`).
Макет должен выглядеть как часть продукта: качество важнее скорости.

> Кит универсальный: в нём нет ни одного имени токена, компонента или слоя. Всё про ДС этого продукта —
> в `figma.config.json` → `profile` (описание полей — `kit/PROFILE.md`). Пока в файлах есть `{{…}}` — сначала `ds-setup`.

## Файлы Figma

| Файл | fileKey | Доступ |
|------|---------|--------|
| **Рабочий** — здесь собираем | `PNp69l0SBA6ttpwbSHvRhK` | чтение и запись |
| Продукт — эталон экранов и ДС | `PNp69l0SBA6ttpwbSHvRhK` (D-claude, он же рабочий — вариант A) | **только чтение** |

Вариант рабочего файла: `A` (A — дубликат продукта, B — новый файл + библиотека ДС, C — чистая ДС).
В read-only файлах не создавать никаких узлов, даже временных.

## Продукт кратко (заполняет ds-setup, подробно — в profile)

- **Платформа:** мобильный веб — квиз-воронки 375×812 в рамке Safari (`Status Bar iOS iPhone` сверху, `Browser iOS / Safari Bottom` снизу), контент во фрейме `Body`, CTA — `Button_bottom`.
- **Цвета:** paint styles (`Brand/*`, `Base/*`, `Accents/*`, `Secondary/*`, `Sage/*`, `Gradient/*`). Фон экрана `Brand/Background` (#FBF6EE), акцент `Brand/Brand` (#0C6760), карточки `Base/White100` с обводкой `Base/Gray20`.
- **Тёмной темы нет.** Бренд-режимы Green/Violet есть в переменных (`Palette`), но на экранах не используются.
- **Шрифты:** заголовки Roboto Serif (`Brand/H1,H2,H5`), остальное Inter (`Body 1/2`, `Caption`, `Footnote`, `Brand/Button`).
- **Шкалы:** переменные `Primitives` с именами-числами (`4`…`64`, `None`) — и для отступов, и для радиусов; карточки r24, кнопки r30.
- **Компоненты** на странице `Design System`: `Button / Primary`, `.Options` (вариант ответа), `Inputs`, `Dropdowns`, `Tabs`, `Modal`/`Overlay`, `Navigation Header`, прогресс-хедер, пейвол-блоки, ~140 иконок 24px.

Платформенные правила: **`kit/platforms/web.md`** — читать вместе с этим файлом.

## Где что лежит

- `figma.config.json` — реестр: `profile` (как устроена ДС), страницы, компоненты, экраны, флоу, `decisions`.
  После каждого изменения обновлять; перед записью перечитывать и править точечно.
- `STATUS.md` — что сделано, вопросы, отклонения. **Читать в начале каждой сессии.**
- `RECIPES.md` — «тип экрана → эталон» и «задача → компонент» этого продукта.
- `templates/feature-brief.md` — формат ТЗ.

## Как запускать скрипты кита

Скрипты `.claude/skills/*/scripts/*.js` не вставляются в `use_figma` как есть: в них нет данных продукта.
Собрать готовый код:

```bash
python3 -I kit/run.py ds-verify/token-audit ROOTS='["12:34"]' -o "$SCRATCH/run.js"
```

и передать содержимое файла в `use_figma` (`code`). `run.py` добавляет профиль (`CFG`), параметры (`PARAMS`) и
общую библиотеку `kit/runtime.js` (`T`). Параметры каждого скрипта описаны в его первых строках.
Свои разовые скрипты тоже собирать через `run.py` (файл в scratchpad) — тогда доступны `T.fill(узел, 'имя токена')`,
`T.C('accent')` (роль цвета из профиля), `T.text`, `T.mkText`, `T.pad/gap/radius` (токен по значению), `T.effect`,
`T.dark(узел)`, `T.role(имя слоя)`, `T.fonts()`, `T.report()` (сырые значения и не найденное).

## Неразрывные правила

1. **Parity с продуктом.** Фича выглядит как часть продукта. Расхождение компонента с продуктом — баг, чинить
   в компоненте, а не оверрайдом на экране. Исключения — только решения пользователя (в `decisions`).
2. **Только из инстансов.** Экраны — из инстансов ДС продукта и (если продукт так делает) системного кита платформы.
   Повторяющийся паттерн — сразу в компонент. Элемента нет в ДС — добавить в ДС (`ds-component`), а не рисовать на экране.
3. **Как в продукте.** Системные элементы берём так же, как продукт: из системного кита или из его собственных
   компонентов. **Видимые элементы продукта на другие (нативные/новые) не менять без «да» пользователя** — сначала
   список «было → станет».
4. **Только токены продукта.** Цвет, текст, эффекты, отступы, радиусы — тем способом, которым они заданы в продукте
   (переменные или стили; см. `profile.color.system`). Сырые значения — только внутри картинок, системного кита
   и там, где в продукте токена нет (записать в `decisions.rawValues`). Своих токенов не заводить без «да».
5. **Тёмная тема — как в продукте, одним действием** (`T.dark`: режим переменных или замена стилей —
   `profile.dark`). Вариантов Appearance не делать. Нет dark в продукте — не делаем, пишем в отчёте.
6. **Ввод текста → клавиатура** (на мобильных платформах): поле в фокусе, клавиатура у низа, поле/шит над ней.
7. **Констрейнты по ролям** (`ds-constraints`). Left/Top по умолчанию запрещён.
8. **Проверка после каждого изменения** (`ds-verify`). Только после неё отчёт. Честно писать, что проверено и что нет.
9. **Спрашивать перед действием:** удаление компонентов и экранов, скачивание файлов, принятие лицензий,
   изменения вне запроса, новые токены.
10. **Источники.** Платформенные вопросы — только первоисточники (Apple HIG, Material, документация продукта).
11. **Решения — в файлы.** Всё, что решили в чате, — сразу в `decisions` и `STATUS.md`. Одна фича — одна сессия.
    Новое знание о ДС продукта (имя токена, роль слоя, способ dark) — в `profile`, а не в голову.

## Как работаем с пользователем

- Отчёт простыми словами, без жаргона API. Сначала результат, потом детали.
- Решать по умолчанию и докладывать; спрашивать только то, что меняет структуру.
- Неясный ответ на вопрос о замене — не менять, переспросить простым нумерованным списком.
- Длинная работа — короткие промежуточные статусы.

## Грабли Figma Plugin API (use_figma) — для любой ДС

**Скрипты и страницы**
- Скрипт атомарен: ошибка откатывает весь вызов. Перед работой с текстом — `await T.fonts()` (все начертания профиля).
- `figma.skipInvisibleInstanceChildren = false` перед `findAll` по вложенным инстансам. Страницу переключать
  `await figma.setCurrentPageAsync(page)`; искать на чужой странице — после `await page.loadAsync()`.
- Никаких бесконечных циклов и `findAll` по всему файлу без фильтра — соединение рвётся.
- `figma.createFrame()` даёт белую заливку и `clipsContent = true`: служебным фреймам — `T.frame()` (без заливки),
  а где внутри тени/блюр — `clipsContent = false`. Иначе белые плашки в dark.

**Auto-layout и размеры**
- Никогда `node.resize(W, 0)` на auto-layout. HUG — `primaryAxisSizingMode = 'AUTO'`, и задавать его **после** `resize()`.
- `layoutMode` — раньше `strokesIncludedInLayout` и `layoutSizing*`.
- Auto-layout фрейм с констрейнтом Bottom растёт вверх при добавлении детей — констрейнт и `y` задавать после наполнения.
- `minHeight`/`minWidth`, constraints и `x`/`y` вложенных слоёв в инстансе не переопределяются — закладывать
  в компонент (вариант, свойство, auto-layout).

**Компоненты и свойства**
- Новый вариант в существующий набор: сначала `set.appendChild(comp)`, потом `componentPropertyReferences`.
- Клон варианта теряет `componentPropertyReferences`.
- `figma.combineAsVariants`: оверрайды инстансов сохраняются, ключи свойств меняются (искать по `k.split('#')[0]`).
- TEXT/INSTANCE_SWAP-свойство набора — одно значение по умолчанию на все варианты.
- Привязка TEXT-свойства сбрасывает стили диапазонов — переназначать после привязки.
- `isExposedInstance = true` — только для инстансов со своими свойствами.
- Перенос узлов внутри SLOT инстанса меняет их id. `swapComponent` сбрасывает размер абсолютных детей.
- `instance.resetOverrides()` сбрасывает и имена слоёв. INSTANCE_SWAP может переименовать вложенный слой иконки.
- INSTANCE_SWAP картинки другого размера не меняет размер слота — для картинок разной высоты SLOT.
- `textTruncation` сбрасывает `maxLines` в 1 — `maxLines` ставить после.

**Цвета и эффекты**
- Bound-цвет: базовый цвет paint = значение переменной (`T.fill` делает сам), иначе скриншот иногда показывает заглушку.
- Привязанная заливка с `opacity` в главном компоненте **не наследуется** инстансами — полупрозрачность токеном с альфой.
- Градиенты на токенах: `gradientStops[i].boundVariables = { color: { type: 'VARIABLE_ALIAS', id } }`.
- У bound-заливок Figma сбрасывает `blendMode`. Вибрантные blend (LINEAR_BURN и т.п.) системных элементов прячут
  белое в dark — на перекрашенных слоях ставить NORMAL.
- Маски над инстансами (особенно с явным режимом переменных) не рендерятся — использовать clip-фреймы.
- Материалы (стекло/блюр), если они есть в ДС: эффект GLASS рядом/внутри другого стекла даёт артефакты рефракции —
  для статичных карточек «фейковый» материал (полупрозрачный токен + blur style).

**Устаревшая отрисовка (самое частое)**
- После клонирования, смены варианта или правки главного компонента превью инстансов устаревает: пропадают
  заголовки, съезжает текст, материал остаётся старого размера. Данные при этом верные.
- Лечение «касанием»: `ds-verify/touch-render` (свойство туда-обратно / FIXED→resize→исходное);
  материалы — `ds-verify/glass-check` (вариант туда-обратно).
- Скриншот сразу после правки бывает устаревшим — перепроверять отдельным вызовом.
- «По данным ровно, глазами нет» — мерить **пикселями** (`ds-verify/scripts/png-center.py`), а не верить данным.

**Системные киты**
- Внутренности системных kit-инстансов **внутри главного компонента** не «лечить» (варианты, размеры клавиш) —
  расходится по всем экранам. Пересоздавать вложенный инстанс целиком, перекраску переносить послойно.
- Размер дочернего слоя kit-инстанса с constraint SCALE не переопределяется — брать ближайший вариант.
- Ужатый/растянутый kit-инстанс (ширина кита ≠ ширине экрана) может рисовать содержимое со сдвигом — проверять пикселями.

**Ассеты и прочее**
- `download_assets` export захватывает фон родителя. Картинки — через `rawImages`: `imageHash` = SHA-1 файла.
- SVG с `<foreignObject>` Figma не импортирует — тег удалить (`extract_svg_group.py` делает сам).
- `outlineStroke()` кладёт результат в корень страницы — сразу `appendChild` в нужный фрейм.
- `figma.createConnector` в design-файле недоступен — стрелки клонировать из шаблона (`ds-flow-arrows`).
- `figma.saveVersionHistoryAsync` через MCP не работает — версию сохраняет пользователь (⌥⌘S / Ctrl+Alt+S).
