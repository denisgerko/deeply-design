# Figma Feature Kit — новые фичи в Figma руками Claude

Универсальный набор для Claude Code: Claude разбирает дизайн-систему **любого** продукта в Figma и собирает
макеты новых фич из её компонентов и токенов — со всеми состояниями, светлой и тёмной темой, стрелками флоу
и пакетом на аппрув. Экраны продукта заново не пересобираются.

**Кит не знает ваш продукт заранее.** В нём нет ни одного имени токена, компонента или слоя. При первом
запуске Claude сам выясняет, как устроена ваша ДС, и записывает это в **профиль продукта**:
- цвета на переменных, стилях или вообще сырые;
- тёмная тема через режимы, через пары стилей или её нет;
- какой шрифт, какие шкалы отступов и радиусов;
- как называются бары и шиты;
- есть ли библиотека.

Все скрипты работают через этот профиль.

## Что внутри

| Файл | Зачем |
|------|-------|
| `CLAUDE.md` | Правила. Claude читает его в начале каждой сессии. `{{…}}` заполняет `ds-setup` |
| `figma.config.json` | Реестр. Главное в нём — `profile`, то есть как устроена ДС продукта. Ещё компоненты, экраны, флоу, решения |
| `kit/PROFILE.md` | Описание полей профиля и три типовых профиля: переменные / стили / без токенов |
| `kit/runtime.js` | Общая библиотека для всех скриптов: токены по именам, роли слоёв, тёмная тема |
| `kit/run.py` | Собирает готовый код для Figma: профиль + параметры + библиотека + скрипт |
| `kit/platforms/*.md` | Правила платформы: `ios`, `android`, `web` |
| `STATUS.md` | Что сделано, вопросы, отклонения. Память между сессиями |
| `RECIPES.md` | «Тип экрана → эталон» и «задача → компонент» вашего продукта. Растёт с каждой фичей |
| `templates/feature-brief.md` | Формат ТЗ на фичу |
| `.mcp.json` | Подключение Figma MCP |
| `.claude/skills/ds-*` | Скилы (ниже) |

### Скилы

| Скил | Когда |
|------|-------|
| `ds-setup` | **Один раз в начале.** Разбор ДС: профиль, компоненты, эталонные экраны |
| `ds-new-feature` | Новая фича по ТЗ, скриншоту или описанию: флоу, все состояния, light + dark |
| `ds-component` | Не хватает компонента или нашлось расхождение с продуктом |
| `ds-reference-screen` | Нужен экран продукта как фон или каркас, а в рабочем файле его нет |
| `ds-assets` | Перенести картинку или иконку из продукта |
| `ds-constraints` | Констрейнты экранов по ролям, тест растяжением |
| `ds-flow-arrows` | Стрелки переходов и заметки Flow Start / End |
| `ds-verify` | Обязательная самопроверка: токены, light + dark, устаревшая отрисовка, сверка по пикселям |
| `ds-pages-tidy` | Порядок на страницах компонентов, аудит дублей |
| `ds-handoff` | Пакет на аппрув: ссылки, состояния, флоу, вопросы, текст для Slack |

## Что подходит

- **Любая ДС:**
  - на переменных с режимами Light/Dark;
  - на paint styles с парами `Light/…` ↔ `Dark/…`;
  - на смеси того и другого;
  - без токенов (тогда Claude предложит, что делать).
- **ДС в том же файле или отдельной библиотекой.** Для библиотеки Claude сохранит ключи токенов в профиль.
- **Любые имена слоёв.** Нестандартные («Шапка», `Header/Main`) Claude допишет в профиль как роли.
- **Платформы:** iOS, Android, Web. Другие — без платформенного файла.

## Установка

1. **Новая папка проекта.** Скопируйте в неё всё содержимое `figma-feature-kit/`, включая скрытые `.claude/` и `.mcp.json`.
   Нужен `python3`, на macOS он уже есть.
2. **Figma MCP.** В `.mcp.json` прописан официальный сервер `https://mcp.figma.com/mcp`. При первом запуске Claude Code
   попросит войти в Figma. Нужно право **редактирования** рабочего файла.
3. **Figma-файлы:**
   - **продукт** — эталон, только чтение;
   - **рабочий** — здесь собираются фичи:
     - **A. Дубликат продукта** (Figma → Duplicate). Проще всего: ДС уже внутри;
     - **B. Новый файл + библиотека ДС**, если ДС опубликована;
     - **C. Чистая ДС** — только если ДС продукта сильно запущена.
4. **Системный кит**, если продукт его использует. iOS — Apple «iOS and iPadOS 26/27», Android — Material 3 Design Kit.
5. **Шаблон стрелок.** Figma API не создаёт коннекторы в design-файле, поэтому один коннектор нужно вставить вручную.
   Скопируйте стрелку из community-файла «Native Figma Flow Arrows» или из FigJam в рабочий файл и назовите её
   `Connector template (hidden)`.

## Первый запуск

```
Прочитай CLAUDE.md и запусти скил ds-setup.
Продукт (только чтение): <ссылка на Figma-файл продукта>
Библиотека ДС (если отдельно): <ссылка>
Рабочий файл: <ссылка>
Платформа: iOS | Android | Web
Эталонные экраны (по желанию): <ссылки с node-id: главная, список, шторка, модалка, форма>
```

Что сделает `ds-setup`:
1. Прогонит детектор и заполнит **профиль**. Спорное покажет вам, а не будет угадывать.
2. Найдёт компоненты и эталонные экраны по типам.
3. **Проверит профиль**:
   - превью компонентов в light и dark;
   - аудит токенов на экранах продукта: если почти чисто, Claude понимает вашу ДС.
4. Заполнит `{{…}}` в файлах и вернёт короткий отчёт с вопросами.

## Новая фича

1. ТЗ по шаблону `templates/feature-brief.md` или свободным текстом, скриншоты — с номерами.
2. Сообщение: `Новая фича по ТЗ ниже, скил ds-new-feature.` и само ТЗ.
3. Claude:
   - спросит только то, что меняет структуру;
   - соберёт страницу `<Фича>` со всеми состояниями, стрелками и тёмной копией;
   - проверит себя и отчитается.
4. Правки — текстом со ссылкой на узел (`node-id` из адреса Figma).
5. Готово → `скил ds-handoff`: Claude подготовит текст для Slack и ссылки.

## Правила, которые сэкономят время

- **Одна фича — одна сессия.** Параллельные сессии перезаписывают `figma.config.json`.
- **Решения — в файлах.** Что решили в чате, попросите записать в `decisions` и `STATUS.md`.
- **Профиль растёт.** Нашёлся новый токен, роль слоя или особенность ДС — это записывается в `profile`, а не держится в голове.
- **Удаление — только после «да».** Своих токенов Claude не заводит без вашего согласия.
- **Замены — списком «было → станет».** Claude не меняет видимые элементы продукта молча.
- **Проверяйте глазами.** Рендер через MCP иногда устаревает. Если видите поломку, дайте ссылку на узел.
- **Версия файла.** Перед большой фичей сохраните версию в Figma (⌥⌘S): через MCP это сделать нельзя.
